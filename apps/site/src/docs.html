AI connectors

Find it in Settings → AI connectors

Workspaced doesn’t run its own AI models. Your assistant talks to third-party models through OpenRouter, so those providers’ terms and privacy policies apply to what you send them.

  • Add a named connector, then choose it for any workspace.
  • Until you pick a model yourself, a workspace uses the cheapest one your connector offers. You can switch at any time from the model menu in chat.
  • Model usage is billed separately from workspace hosting.
  • Every account gets a protected Trial connector with a small budget to try things out. It doesn’t refill.

Your prompts, plus any context the assistant needs, go to the provider you selected. Always check the assistant’s work before relying on it.

Workspaces

A workspace is your own computer in the cloud. Its assistant can install software, edit files and run apps while you chat with it.

  • All sessions in a workspace share the same files and running services.
  • Your apps keep running after you close the browser.
  • A free trial lasts four hours. When it ends, the machine and everything on it is permanently deleted, unless you keep it: Keep it on the trial’s banner turns it into a workspace of your own on the same machine, with nothing lost, paid from your balance from then on.

Recipes

Find it in the Store

A recipe is a reusable set of instructions for the assistant. Browse public recipes in the Store, or keep private ones of your own. Choose New recipe to write instructions from scratch or import a Markdown file.

Before you apply a recipe, read its steps and check who wrote it. Applying it starts a new session in the workspace you pick.

New here? Search for Simple web page by workspaced. It builds a friendly demo page, asks you in chat before making it public, publishes it and hands you the link. From there, just ask for whatever changes you like.

MCP servers

Find it in Workspace settings → MCP servers

MCP (the Model Context Protocol) is an open standard that lets an AI assistant use tools from other services. Each MCP server adds a set of abilities. One might let the assistant read and update issues in your project tracker, another might let it search your notes or query a database.

Without MCP, the assistant can only work with what’s inside the workspace: its files, its terminal and the web. With MCP, it can work directly in the tools you already use.

In settings you can add a server, switch it on or off, and see whether each one is connected and working.

From chat: just ask, for example “Connect the GitHub MCP server” or “Turn off the calendar server.” The assistant sets it up and switches it on for you, and it shows up in settings like any other.

  • Only connect services you trust, and check what access they get.
  • Keep any credentials they need in Secrets, never in the server settings or in chat.
  • The service itself may need its own account or subscription.

Secrets

Find it in Workspace settings → Secrets

Secrets store sensitive values like passwords and API keys. Give each one the exact name your app or recipe expects.

  • Saved values stay hidden. After a restart, the assistant’s tools can read them as environment variables.
  • Restarting applies the new values and keeps your files and conversations.
  • Never paste a secret into chat, a public recipe or your page’s HTML.

Variables

Find it in Workspace settings → Variables

Variables are named settings for your apps that aren’t sensitive, such as a preferred language. Anything secret belongs in Secrets instead.

You also set the workspace time zone here, so the assistant reads times like “9 am” the way you mean them. If the app says a restart is needed, restart to apply your changes.

Sessions

Find it in Workspace settings → Sessions

A session is one conversation with the assistant. Start a new one for a separate piece of work, or reopen an old one to pick up where you left off.

Because every session shares the workspace’s files, a change made in one can show up in another. Settings also control how long inactive sessions are kept.

Firewall

Find it in Workspace settings → Firewall

Your workspace is closed to the internet by default. The firewall decides which ports, if any, people outside it can reach. Starting a server, such as a website on port 80, doesn’t make it public on its own. It stays private until you open its port.

Each rule opens one TCP port. You can also limit who can connect by filling in From with an IP address or range. Leave it empty and anyone on the internet can reach that port.

From chat: ask things like “Make my page public” or “Close port 8080.” The assistant manages ports for you and always asks before opening one. This is on by default; switch off the permission on this screen if you’d rather handle ports yourself.

  • The demo page is served on port 80 over plain HTTP, which isn’t encrypted. Don’t collect passwords or personal data on it.
  • Close ports you no longer need.
  • Keep private tools, admin panels and credentials off public ports.

Instructions

Find it in Workspace settings → Instructions

Instructions are lasting notes the assistant reads at the start of every conversation in a workspace. Think of them as a short briefing you’d give a new teammate: how you like things done, and what they need to know about your project.

Good things to keep here:

  • Your preferences, like “Write in British English” or “Keep replies short.”
  • How your app works: where it lives, how to start it, how to deploy a change.
  • Decisions you’ve made, so you don’t have to explain them again in each session.

From chat: say “Remember that…” or “Add to the instructions that we deploy with ./deploy.sh.” The assistant updates them and you can review the result in settings at any time.

Instructions shape how the assistant behaves, so never put passwords or API keys in them. They’re optional, and you don’t need any to build the demo page.

Tasks

Find it in Workspace settings → Tasks

Tasks let the assistant work without you. A task is a prompt plus a time: run it once later, or repeat it on a schedule. Each run starts its own session, so you can open it afterwards and see exactly what the assistant did.

Use tasks for things you’d otherwise have to remember: checking that your site is up, collecting the day’s news on a topic, cleaning up old files, or sending yourself a weekly report.

From chat: this is the easiest way to create one. Ask for what you want and when:

  • “In 30 minutes, check my page.”
  • “Every weekday at 9 am, write me a summary.”
  • “Stop the daily summary task.”

In settings you can review, edit or delete each task’s prompt and schedule. Tasks only run while the workspace is running, each run spends your AI connector’s budget, and tasks are deleted along with their workspace.
